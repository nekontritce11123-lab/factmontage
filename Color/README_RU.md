# Studio Color 0.1.0 — «Цвет» для монтажной студии

**Экспериментальные исходники, не установочный Flatpak и не проверенный релиз Kdenlive.**

В `Color/` изолированы C++-ядро, LUT 33³, AVX2 со скалярным резервом,
анализ без нейросетей, планирование группового выравнивания, MLT-адаптер
`studio.color`, генератор контракта и восемь встроенных стилей. Прототипные
`ColorPanel`, `ColorHost`, `DemoHost` и отдельное хранилище пресетов в проект не перенесены:
цвет встраивается в единую `StudioPanel`, а источником состояния остаётся проект Kdenlive.

**Единственный источник статуса — `docs/TEST_REPORT_RU.md`.** Не считать наличие
исходного файла доказательством работы в редакторе.

## Сценарий версии 1.0

Выбрать визуальный клип → добавить цвет → выбрать один из восьми стилей →
при необходимости изменить яркость, теплоту, контраст и насыщенность.
Обработка SDR, 8 бит; звук не меняется. Выбранный стиль выделяется в панели.

Автоматическое выравнивание и выбор эталона в этот выпуск не входят. Код анализа
и ранее сохранённые автоматические параметры сохранены для совместимости;
неприменимый регулятор силы выравнивания скрыт. Наличие CLI анализа не означает
наличие этой функции в панели Kdenlive.

## Содержимое

- `Color/src/`, `Color/include/`: движок, анализ, SIMD и локальный CLI для проверок; CLI в приложение не устанавливается.
- `Color/scripts/generate_ui.py`: единственный источник параметров и готовых стилей;
  из него получаются C++-контракт, XML, JSON, YAML и файлы пресетов.
- `Color/mlt/`: адаптер MLT 7; в воспроизведении нет анализа, декодирования файлов или Python.
- `Color/tests/`: изолированные проверки ядра, контракта, CLI/FFmpeg и MLT smoke-test.
- `docs/`: алгоритмы, исследование библиотек, интеграция и результаты проверок.
- `scripts/`: проверка сборки, экспорт LUT и синтетический материал для воспроизведения тестов.

## Проверить ядро на машине разработчика

Требуются CMake ≥3.20 и C++17-компилятор; Python3 нужен генератору/тестам, не воспроизведению.
FFmpeg необязателен, но позволяет выполнить независимое сравнение интерполяции.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/studio-color presets
./build/studio-color benchmark 1920 1080 40 --preset sunimo
```

Санитайзеры:

```bash
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=RelWithDebInfo -DSTUDIO_COLOR_SANITIZE=ON
cmake --build build-asan --parallel 2
ctest --test-dir build-asan --output-on-failure
```

Это команды разработки, **не инструкция компилировать что-либо на Deck**.
Конечная доставка по архитектуре студии — отдельный Flatpak, собранный в закреплённом SDK.
`org.kde.kdenlive` не заменять, системный раздел SteamOS не менять.

## Что можно попробовать без сборки нового редактора

Из `Color/luts/` взять `.cube` и выбрать его в штатном эффекте Kdenlive «Применить LUT»
(Apply LUT). Интерполяция — тетраэдральная. LUT не добавляет нашу панель и не выравнивает
клипы автоматически. Файлы рассчитаны для обычного SDR BT.709; не подавать непосредственно
HDR, LOG или материал с неизвестным преобразованием. Для проекта LUT остаётся внешним
файлом: сохранить его рядом с материалами и не переносить без обновления пути.

## Границы

Только прямой RGBA8888, RGB полный диапазон, основные цвета Rec.709; передаточная
функция BT.709 или sRGB задаётся явно. Ограниченный YUV-диапазон и преобразования
источника — задача проверенного хоста, не ручное дополнительное сжатие 0–255 в 16–235.
Нельзя восстановить фактуру, уже утраченную в белом пересвете. Автоматика не знает
художественный замысел и не гарантирует идеальное совпадение любых сюжетов.
Меняющийся свет/склейки внутри клипа консервативно пропускаются: временной
дефликер, маски, кожа, HDR/LOG, RAW и вторичный цветокор в 0.1.0 не реализованы.

Подробно: `docs/DESIGN_RU.md`, `docs/RESEARCH_RU.md`, `docs/INTEGRATION_RU.md`.
