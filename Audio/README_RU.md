# StudioAudio 0.2 — обработка звука для монтажной студии

Здесь находится изолированный C++ worker и его единый генерируемый контракт.
Qt-контроллер живёт в `Studio/overlay/audio/`; сборка Kdenlive, Flatpak и Steam Deck
пока не проверены. Фактический статус — только `docs/TEST_REPORT_RU.md`.

## Что реализовано

**Голос:** мягкая обработка с одним ползунком силы, удаление низкочастотного гула,
необязательное шумоподавление, деэссер и компрессор. Чистый голос по умолчанию
не проходит через нейросетевое шумоподавление. Есть полное отключение обработки
при силе 0 и шумоподавлении «Не убирать шум»; преобразование формата остаётся.

**Музыка:** отдельная нормализация без речевых фильтров. В режиме «Голос + музыка»
есть заметность подложки и приоритет голоса. Музыка плавно приглушается до начала
звучащей фразы и возвращается после паузы, а не дёргается от каждого слога.

**Общая нормализация:** выбранная программа целиком, а не каждый маленький разрез
по отдельности. Двухпроходный `loudnorm`, затем проверка готового WAV фильтром
`ebur128`; при необходимости — не больше двух поправок постоянного усиления
с повторным измерением. По умолчанию −16 LUFS, потолок −1,5 dBTP.
Нормализация отдельно применима к голосу, музыке или уже собранному миксу.

**Паузы:** `silencedetect` на голосовом стеме возвращает только абсолютные интервалы
удаления. Внутренняя пауза длиннее 650 мс сохраняет 180 мс после предыдущей фразы и
120 мс перед следующей; worker не редактирует монтаж и не создаёт WAV.

**Панель:** «Голос» / «Громкость» / «Музыка» / «Паузы», готовые и пользовательские
шаблоны, прогресс, отмена и одна главная кнопка. Применение выполняет контроллер
закреплённого Kdenlive одной транзакцией отмены.

## Что важно понимать

Голос и музыка для автоматического баланса должны быть отдельными дорожками.
Модуль не отделяет голос от уже сведённой песни и не восстанавливает потерянные
при записи данные. Детектор пауз — энергетический, не семантическое распознавание
речи. Постоянный шум, телевизор или музыка в микрофонной дорожке могут вызвать
ложное приглушение. Реальные записи необходимо прослушивать.

Рабочая версия предварительно рассчитывает обработанный аудиофайл. Она не
создаёт новый MLT-эффект `studio.voice`, не меняет системный звук PipeWire
и не устанавливает новый общий аудиодвижок. Воспроизведение результата должен
выполнять штатный MLT в составе существующей студии.

Это осознанное отличие от исходного `AUDIO_PLAN_RU.md`, где предполагалась
живая цепочка существующих эффектов. Готовый WAV снижает повторную вычислительную
работу при воспроизведении, но требует дискового кэша и перерасчёта после изменения
исходников. Эквивалентность в реальном GUI/экспорте ещё должна быть проверена.

## Сборка и запуск обработчика

Команды предназначены для Linux / WSL с уже установленными CMake, Ninja,
C++17-компилятором, FFmpeg и ffprobe. **Не устанавливать эти инструменты
в системный раздел SteamOS.** Для конечной поставки нужна сборка в закреплённом
Flatpak SDK вашей студии.

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
ctest --test-dir build --output-on-failure
python3 tests/integration.py --worker build/studio-audio --report build/integration.json
```

Только голос:

```bash
./build/studio-audio \
  --mode voice \
  --voice "/полный/путь/голос.wav" \
  --out-dir "/полный/путь/новый-результат-голос" \
  --strength 40 --noise off --normalize on --target -16
```

Голос с музыкальной подложкой:

```bash
./build/studio-audio \
  --mode mix \
  --voice "/полный/путь/голос.wav" \
  --music "/полный/путь/музыка.wav" \
  --out-dir "/полный/путь/новый-результат-микс" \
  --strength 40 --presence 50 --priority 60 --noise off \
  --normalize on --target -16 --true-peak -1.5
```

Только музыка:

```bash
./build/studio-audio \
  --mode music \
  --music "/полный/путь/музыка.wav" \
  --out-dir "/полный/путь/новый-результат-музыка" \
  --normalize on --target -16
```

Анализ пауз:

```bash
./build/studio-audio \
  --mode pauses \
  --voice "/полный/путь/голос.wav" \
  --out-dir "/полный/путь/новый-отчёт-пауз"
```

Папка результата **не должна существовать**. Исходники не перезаписываются.
В режиме mix оба файла начинаются в одной точке монтажного времени; нужную
тишину перед вступлением голоса нужно сохранить. Короткая дорожка дополняется
тишиной до конца длинной. Это не автоматическое определение сдвига двух файлов.

## Результат

`result.wav` — стерео PCM 24 бит / 48 кГц, `report.json` — измерения, параметры,
SHA256 и предупреждения, `ducking.tsv` — диагностические точки приглушения.
Результат публикуется одной операцией переименования временной папки после
успешной обработки. Отмена и обычная ошибка удаляют временный результат.
Это не гарантия сохранности при внезапном отключении питания: отдельный fsync
не реализован. Необработанные SIGKILL/авария питания могут оставить временную папку.

Код возврата 0 означает, что обработка завершена, **но не обязательно** что
громкость достигла цели: проверяйте `target_met` и `warnings` в JSON.
Код 130 — отмена, код 1 — ошибка. При тишине цель LUFS не объявляется достигнутой.

## Ограничения текущей реализации

Моно/стерео, от 0,4 секунды до двух часов. Многоканальный звук отклоняется.
Нет AI-разделения вокала, устранения сильного эха, облачных API,
изменения высоты голоса, генерации музыки и маскировки повреждённой записи.
RNNoise предусмотрен как отключаемая LADSPA-ветка, но сама библиотека не входит
в архив и этот путь ещё не прошёл приёмку.

Не создавайте отдельный отчёт Audio: подтверждённые результаты записываются только
в общий `docs/TEST_REPORT_RU.md`.
