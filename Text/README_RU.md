# FactMontage Text

Нативный движок надписей в общем разделе «Текст» FactMontage. Панель использует Qt; отдельный web-редактор остаётся инструментом разработки. STXT v1/v2/v3 и существующие ID сохранены.

Сборка приложения: [BUILD_RU.md](../docs/BUILD_RU.md). Сведения ниже описывают движок и его отдельные инструменты, а не приёмку итогового Flatpak.

**100 переходов + 100 подобранных продолжений жизни текста.** Отдельный модуль для последующего внедрения в ваше приложение и нативный Frei0r-фильтр для Kdenlive. Это не новый встроенный док Kdenlive.

Главное изменение: титр больше не заканчивает свою анимацию после появления. У него есть три согласованные фазы: **появление → жизнь → исчезновение**. Характер средней части берётся из выбранного входа или выбирается отдельно.

## Быстрый запуск / обновление

Закройте прежнюю панель и Kdenlive. Распакуйте новую версию в отдельную папку. Не удаляйте ранее экспортированные сцены и проекты.

В терминале из папки этой версии:

```bash
bash install.sh
bash launch.sh
```

Затем откройте Kdenlive заново. Установщик обновит одноимённую библиотеку, сохранив пути других Frei0r-плагинов. Полной интеграционной проверки установщика на физическом Steam Deck не было. Сначала проверьте на отдельном тестовом титре.

Готовая библиотека — Linux x86-64, **glibc ≥ 2.38**. Она не собрана с `-march=native`. При несовместимой среде есть исходники и `build.sh`; установщик проверяет загрузку в среде Kdenlive. Подробности: `docs/INSTALL_RU.md`.

## Как пользоваться новой жизнью текста

1. Выберите переход слева и напишите текст. В разделе «Движение → Жизнь после появления» по умолчанию стоит **«Авто · характер выбранного перехода»**.
2. Регулируйте **«Живость»** и **«Темп»**. Это отдельные настройки средней части, они не изменяют длительность входа и выхода. Кривые и ограничения уже настроены внутри профиля.
3. Нажмите **«Смотреть середину»**, чтобы зациклить только фазу чтения в превью. **«Только жизнь»** отключает оба перехода, сохраняя характер движения. «В Kdenlive» создаёт `.stxt` и `.mlt`.

Полученный `.mlt` добавьте в корзину проекта и на видеодорожку выше основного видео. Соседний `.stxt` нужен для воспроизведения; он хранит настройки и изображения букв. MLT-файл содержит абсолютный путь к сцене.

Чтобы полностью остановить надпись, выберите **«Без движения»** в разделе жизни или установите «Живость» в ноль. Отключение появления и исчезновения само по себе жизнь не выключает.

## Что изменено

**Разный характер.** У пружины — редкие упругие импульсы; у змейки — связная волна; у переворотов — небольшие перспективные покачивания; у цифровой сборки — короткие цифровые сбои; у спокойной подписи — очень сдержанный дрейф. Маски в средней части не раскрываются повторно и не скрывают готовые буквы. Фокусные варианты не держат текст постоянно размытым.

Это **100 настроенных профилей на 25 используемых механиках**, а не 100 полностью независимых алгоритмов. Полный список находится в `docs/LIFE_CATALOG_RU.md`. Прежние 100 переходов работают на 48 механиках.

**Цельные слова и строки.** Исправлена старая ошибка: остаточная анимация использовала индекс каждого спрайта даже при группировке по словам/строкам. Теперь выбранная группа получает одинаковое локальное преобразование, а общее дыхание применяется к единому блоку. Специальный эффект интервала остаётся исключением по замыслу: он слабо меняет позиции относительно центра каждой строки, не накапливая сдвиг.

**Вёрстка букв.** Измерение ширины, перенос и положение букв используют один план advance/kerning. Ширина целого префикса больше не смешивается с растеризацией отдельных знаков. Опорная вертикаль общая для строки. Русский, латиница и графемные диакритические последовательности поддерживаются; полноценного OpenType-shaping для связанных письменностей нет.

**Плавные стыки.** Средняя фаза использует одну абсолютную шкалу времени и плавную огибающую возле переходов. Другой выход не переключает характер жизни в середине титра. Случайные параметры детерминированы: перемотка не создаёт новый рисунок движения.

**Смешивание.** Второй переход продолжает участвовать в автоматической жизни. Его вклад в средней части ограничен: основной характер получает вес `1 − 0.5 × примесь`, дополнительный — `0.5 × примесь`. При выборе отдельного характера в списке «Характер» он используется самостоятельно.

**Предпросмотр.** Параметры анимации не требуют повторной растеризации неизменившегося текста: в компиляторе есть односценовый кэш вёрстки. Для кадров панель использует RGBA вместо PNG-кодирования каждого кадра. Одновременно выполняется один запрос кадра; устаревший результат после перемотки не показывается. Разрешение воспроизведения снижается при нагрузке; остановленный кадр рассчитывается до 768 × 432. Это относится только к превью, а не к экспортной сцене. Предпросмотр ограничен максимум 30 кадрами/с; окончательный рендер использует FPS сцены.

## Демо и проверки

`demo/lifecycle_v02.mp4` — **60 секунд, 960 × 540, 30 кадров/с**. Семь сцен показывают по 5,3 секунды средней фазы; восьмая — движение без входа/выхода. Все анимированные пиксели рассчитаны той же нативной библиотекой, а не отдельной браузерной имитацией. В демо установлена живость 85%, в новых сценах по умолчанию 65%.

Пройдены **31 автоматический тест**. Они проверяют прежние переходы, все 100 профилей жизни, группировку, отсутствие накопленного дрейфа, стыки фаз, чтение старых сцен, режим без движения, отдельную жизнь без переходов, смешивание, прозрачность, API, защиту локального сервера и RGBA-кадры. Вывод: `docs/TEST_OUTPUT_V02.txt`.

Дополнительно проверены интерфейс и Canvas-компилятор в Chromium с тестовым HTTP-мостом из Python. Обычная навигация Chromium к localhost в контейнере заблокирована администратором; тест не выдаётся за полноценный запуск браузера через localhost на SteamOS. Серверные HTTP-тесты выполнялись отдельно. Подробности: `docs/TEST_REPORT_V02_RU.md`.

**Физический Steam Deck, реальный Kdenlive/MLT и Flatpak-хост в этой среде не тестировались.** Значения из `docs/BENCHMARK_LIFE_CONTAINER.json` относятся только к контейнеру, не являются обещанием FPS на Deck и не включают декодирование видео, MLT и интерфейс.

## Совместимость и ограничения

Новые сцены имеют **STXT v2**. Новая библиотека читает v1 и v2; старая 0.1 не умеет читать v2. Обновляйте библиотеку вместе с панелью. При открытии старого черновика прежний стандартный режим «плавание, 25%» переводится в новый автоматический профиль; явно отличающиеся ручные настройки сохраняются. Уже экспортированные старые файлы не переписываются установщиком.

Старые сцены остаются читаемыми; исправление группировки меняет ошибочное старое поведение ручной жизни. Пиксельная идентичность всех старых анимированных сцен не обещается.

После обрезки клипа на таймлайне выход не привязывается автоматически к новому краю: измените длину сцены и экспортируйте её заново. Это ограничение Frei0r-адаптера не устранено этой версией. При включённой жизни вся последовательность не обязана быть зеркально симметричной; «реверс» относится к переходу. Для точного зеркального совпадения кадров выключите жизнь.

Размер кадра, число букв, тени, расфокус, эхо и временное размытие влияют на нагрузку. На слабой машине начинайте без motion blur; заранее просчитанный прозрачный MOV доступен через `tools/render.py`, при наличии внешнего FFmpeg. Поддерживаются не более 240 видимых графем и 16 строк в панели. Шрифты не включены в архив: используйте системные или свои TTF/OTF.

## Для внедрения

- `web/compiler.js` — `compileScene`, `sanitize`, `readSceneMetadata`, `clearLayoutCache`.
- `tools/make_catalog.py` + `tools/life_catalog.py` — источники каталога; `src/recipes.inc`, `src/life_recipes.inc`, `web/catalog.json` генерируются из них.
- `src/engine.hpp`, `src/life.hpp`, `src/plugin.cpp`, `src/sunimo_text_api.h` — независимый C++17-рендерер, Frei0r и C API.
- `studio.py` — заменяемый локальный адаптер панели; `docs/ARCHITECTURE_RU.md` — двоичный контракт и границы интеграции.

Проверки и сборка:

```bash
bash build.sh
python3 -m unittest discover -s tests -v
python3 tools/benchmark_life.py --frames 90
bash doctor.sh --mlt-smoke
```

Последняя команда требует доступного реального MLT; её успех в этой поставке не заявлен.
